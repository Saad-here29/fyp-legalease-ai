# API Reference

> The full live OpenAPI schema is generated by FastAPI at
> `http://localhost:8000/docs` (Swagger) and `/redoc` (ReDoc) in dev mode.
> This file documents conventions and major endpoint groups.

## Base URL

```
Production:  https://api.legalease.ai/api/v1
Development: http://localhost:8000/api/v1
```

## Authentication

All endpoints except `/auth/*` and `/health` require:

```
Authorization: Bearer <access_token>
```

## Endpoint Groups

| Prefix | Module | Notes |
|--------|--------|-------|
| `/auth` | Authentication | login, signup, refresh, OTP, forgot-password |
| `/users` | User management | profile, list (admin) |
| `/cases` | Case Management | CRUD, status, hearings, timeline |
| `/documents` | Documents | upload, analyze, download |
| `/chat` | AI Chat | sessions, ask, history |
| `/research` | Legal Research | semantic search, similar cases |
| `/ocr` | OCR | upload, job status |
| `/contracts` | Contract Drafting | templates, drafts, compliance |
| `/simulator` | Practice Simulator | scenarios, attempts, progress |
| `/notifications` | Notifications | list, mark-read |

## Response Envelope

Successful responses return the resource directly:

```json
{ "id": "uuid", "title": "...", ... }
```

Errors are structured as:

```json
{
  "error": {
    "code": "invalid_credentials",
    "message": "Invalid email or password.",
    "hint": "Double-check your email and password."
  }
}
```

Every error has a `hint` field per USE-04 (every error message has a description and a fix hint).

## HTTP Status Conventions

| Code | Meaning |
|------|---------|
| 200 | OK (read or update) |
| 201 | Created |
| 204 | Deleted |
| 400 | Bad request (validation) |
| 401 | Unauthenticated |
| 403 | Unauthorised (RBAC) |
| 404 | Not found |
| 409 | Conflict (illegal state transition) |
| 413 | Payload too large |
| 415 | Unsupported media type |
| 423 | Account locked |
| 503 | AI service unavailable |
