# Development Guide

For first-time setup, see the root `README.md`. This page covers day-to-day
work.

## Prerequisites

- **Software:** Python 3.11, Node.js 20+.
- **Database:** a PostgreSQL URL in `backend/.env` (`DATABASE_URL`). The team
  uses a Supabase project. There is no Docker setup and no Redis/Celery.
- **AI:** a Groq API key (`GROQ_API_KEY`).
- **Large files that aren't in git:** the FAISS index
  (`backend/storage/faiss/`) and the NER model
  (`backend/storage/models/legal_ner/`); see `ai-services/README.md`.
- **For scanned PDFs and images:** Tesseract OCR with English and Urdu data
  (`TESSERACT_CMD` in `backend/.env`). Poppler isn't needed.

## Running both servers

Run each in its **own terminal window**, and leave both open:

```powershell
# backend — http://localhost:8000 (API docs at /docs in development)
cd backend
venv\Scripts\activate
set HF_HUB_OFFLINE=1
set TRANSFORMERS_OFFLINE=1
uvicorn app.main:app --port 8000

# frontend — http://localhost:5173 (proxies /api to :8000)
cd frontend
npm run dev
```

- **Restart the backend after changing backend code.** `--reload` works,
  but each reload re-loads the embedding and NER models.
- **Signup and reset codes** are printed in the backend window
  (`[DEV OTP] …`) unless the SMTP settings are filled in.

## Tests, lint, build

```powershell
cd backend
pytest                      # whole suite, offline: SQLite in memory, no AI calls
pytest app/tests/unit/test_case_service.py -q
ruff check app

cd frontend
npm run lint
npm run build
```

- **Offline tests:** the backend tests never call the language model.
  Model-dependent code is tested with stubs. Keep it that way: every Groq
  call spends the shared daily budget (200k tokens/day; see
  `docs/archive/PROJECT_CONTEXT.md`).
- **Frontend tests:** there are none yet.

## Database changes

```powershell
cd backend
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

Review an autogenerated migration before applying it.
`docs/database-schema.md` lists the existing migrations.

## Conventions

- **Backend:**
  - routers stay thin; business rules and role checks live in `services/`;
  - errors are `AppException` subclasses (`core/exceptions.py`) with a
    `code`, `message` and `hint`;
  - no database transaction may stay open across an LLM call (the Supabase
    pooler kills idle transactions); see `legal_chat_service.py` for the
    three-phase pattern.
- **Frontend:**
  - design system v1 only (`docs/STYLE_GUIDE.md`): `ds-` tokens and
    classes, Newsreader and IBM Plex Sans;
  - API paths live in `src/api/endpoints.js`.
- **Naming:**
  - PascalCase for components and classes;
  - camelCase for JS functions;
  - snake_case for Python and database columns;
  - kebab-case for frontend feature folders.
- **Commits:** small and focused, with a message that says what changed and
  why.
